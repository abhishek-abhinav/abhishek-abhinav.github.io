01 / PROJECT OVERVIEW

What this system is designed to do

A WhatsApp-based task interaction system designed around a dedicated Meta WhatsApp Cloud API number, role-aware routing and a spreadsheet-backed task system.

The solution is implemented as an n8n-led workflow using the integrations and logic described below. The focus is to connect the input, processing steps and destination systems into a traceable flow. The workflow checks the sender against registered contact data, identifies their role and routes the request to the appropriate task interaction path.

02 / BUSINESS CONTEXT

The problem and objective

Task requests arriving through WhatsApp need to be interpreted in the context of who sent them. Owners and employees require different task interactions, while the task record needs to remain consistent.

Objective: Build a repeatable workflow that connects the relevant data or event to the appropriate processing logic and records the result in the systems used by the team.

03 / IMPLEMENTATION SCOPE

What I implemented

  • Identify contacts using registered phone numbers
  • distinguish owner and employee roles
  • route incoming messages to role-specific flows
  • allow owners to initiate and assign tasks
  • support employee-side task processing
  • update task status in the backend sheet
  • validate incoming requests and handle errors
04 / WORKFLOW ARCHITECTURE

How the workflow operates

The workflow checks the sender against registered contact data, identifies their role and routes the request to the appropriate task interaction path.

  1. 01

    Receive the WhatsApp message

    A message arrives through the dedicated WhatsApp Cloud API number and triggers the webhook.

  2. 02

    Identify the sender

    The workflow checks the sender's phone number against registered contact information.

  3. 03

    Determine the role

    The system distinguishes owner and employee paths and routes the request to the relevant interaction flow.

  4. 04

    Process the task request

    The owner-side path supports task assignment; the employee-side path supports task processing and updates.

  5. 05

    Update the backend record

    Task details and status are maintained in the connected Google Sheet, with validation and error handling.
